# BlueShield 🛡️

**צנזור אוטומטי ומקומי לסרטונים ולתמונות.** BlueShield מזהה את האנשים שבסרטון או בתמונה, מעריך לגבי כל אחד אם הוא אישה או גבר ומה גילו, ומכסה את העור החשוף ואת האזורים הרגישים **של מי שנבחר לצנזור בלבד**. כברירת מחדל אלה נשים בוגרות. הכיסוי הוא בצבע לבחירתכם: לבן כברירת מחדל, או שחור, אפור, בז', כחול, צבע מותאם, או הבהוב מונפש. הוא עוקב אחרי צורת הגוף ואחרי התנועה. הפנים, הצוואר וטקסט שמופיע על המסך (כתוביות) תמיד נשארים גלויים, ושאר הסרטון לא משתנה.

> 🔒 **כל העיבוד מקומי.** בדסקטופ השרת מאזין רק ל-`127.0.0.1`. אפליקציית האנדרואיד לא מבקשת בכלל הרשאת אינטרנט.

הכלי מיועד לצנזור בלבד: הוא מזהה ומסתיר אזורים, ולעולם לא יוצר, משפר או משחזר תוכן.

| גרסה | תיקייה | טכנולוגיה | סטטוס |

## 1. הרצת הדסקטופ

דרישות: Python 3.10–3.12, ‏Node.js 18+, ‏FFmpeg.
(`brew install ffmpeg` / `sudo apt install ffmpeg` / `winget install Gyan.FFmpeg`)

```bash
./start.sh            # macOS / Linux   (או desktop/start.sh)
start.bat             # Windows
```

הסקריפט יוצר `desktop/.venv`, מתקין תלויות, בונה את הממשק, מוריד מודלים ופותח את **http://127.0.0.1:8765**.

הפעלה ידנית:
```bash
cd desktop
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
(cd frontend && npm install && npm run build)
python scripts/download_models.py
cd backend && python run.py --open          # --port 9000
```

בדיקות: `pip install pytest && python -m pytest desktop/backend/tests -q` (‏28 בדיקות).

## 2. בניית ה-APK לאנדרואיד

דרישות: ‏**JDK 17+** ו-**Android SDK** (Android Studio, או command-line tools) עם `platforms;android-35` ו-`build-tools;35.0.0`.

```bash
cd android
echo "sdk.dir=$HOME/Android/Sdk" > local.properties   # או export ANDROID_HOME=...
./gradlew assembleDebug
```

### 3. מיקום ה-APK
```
android/app/build/outputs/apk/debug/app-debug.apk
```
התקנה: `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`, או העתקה לטלפון ופתיחה.
גרסת release: ‏`./gradlew assembleRelease` (כרגע חתומה במפתח debug. לפני הפצה חותמים במפתח משלכם).

אפשר גם לפתוח את התיקייה `android/` ב-Android Studio וללחוץ Run.

> ⚠️ **שקיפות:** בסביבת הפיתוח שבה נכתב הקוד, מדיניות הרשת חוסמת את `dl.google.com`, ולכן גם את Maven של Google. בלעדיהם אי אפשר להוריד את ה-Android SDK, את Android Gradle Plugin, את AndroidX/Compose ואת אמולטור. לכן **ה-APK לא נבנה ולא הותקן על מכשיר או אמולטור**. מה שכן נבדק:
> * **`android/core`, כל צינור העיבוד ב-Kotlin**, נבנה ונבדק עם Gradle על JVM, כולל הרצה מלאה עם המודלים האמיתיים על סרטונים אמיתיים (`gradle -p android/core test`): האישה סווגה כאישה, הגבר כגבר, רק צד האישה נצבע, וסרטון של גברים בלבד לא צונזר. בנוסף בדיקת עומס על סרטון של 61 שניות ועל סרטון 1080p עם 984 פריימים, עם זיכרון יציב של כ-130MB.
> * **כל קוד האפליקציה** (ממשק Compose, ViewModel, השירות, MediaCodec/OpenGL/MediaMuxer) עבר בדיקת טיפוסים מלאה מול מחלקות ה-framework האמיתיות של AOSP (`android/tools/sdkless-check`). הבדיקה מצאה ותיקנה 2 באגים אמיתיים, וסקירת קוד של מסלול הרינדור מצאה באג שלישי (סיבוב כפול של סרטונים לאורך) שתוקן ונבדק.
> * לא נבדקו: ריצה על מכשיר (פענוח/קידוד חומרה, ה-shader, שמירה לגלריה, ביצועים בטלפון).
>
> לבנייה בסביבה הזו צריך לאפשר את `dl.google.com` בהגדרות הרשת של הסביבה. מחשב רגיל עם Android Studio בונה את הפרויקט כמו שהוא.

## 4. ארכיטקטורת האנדרואיד

```
 Photo Picker (בלי הרשאות) ──► VideoMeta (MediaExtractor/MediaMetadataRetriever: רזולוציה, סיבוב, FPS, אודיו)
                                   │
 ProcessingService (foreground, התראת התקדמות, ממשיך גם כשהמסך כבוי) ──► Processor
   ├─ ניתוח:   MediaCodec (פענוח חומרה, YUV) ─► RGB זקוף בגודל ניתוח ─► android/core Analyzer (מנות של פריימים)
   │           └─ ONNX Runtime ‏(CPU, ליציבות): סגמנטציה · אנשים · פנים · מגדר · NudeNet
   │           └─ מסכות נשמרות דחוסות בקובץ cache, רק אינדקס בזיכרון
   └─ רינדור:  MediaCodec ─► SurfaceTexture ─► OpenGL ES shader (מסכה מרוככת + כחול/shimmer)
               ─► מקודד H.264 חומרה (input Surface) ─► MediaMuxer ‏(MP4, ‏timestamps וסיבוב מקוריים)
               └─ אודיו: העתקה כמו שהוא (AAC), או המרה ל-AAC כשה-MP4 לא תומך במקור (Opus/Vorbis)
 Compose UI: בית ← הגדרות ← עיבוד (שלבים, פריים/סה"כ, זמן נותר, תצוגה חיה, השהיה/ביטול)
             ← תוצאה (Wipe / מקור+מצונזר / מצונזר בלבד, רשימת אנשים ועקיפה ידנית, שמירה לגלריה, שיתוף)
 שמירה: MediaStore ‏(Movies/BlueShield, בלי הרשאות ב-Android 10+) · שיתוף: FileProvider
```

* **מודול `core` ב-Kotlin טהור.** אותה לוגיקה כמו בדסקטופ: מעקב, הצבעות מגדר, בעלות על פיקסלים, Optical flow ‏(Lucas–Kanade), איחוד זמני ומאגר מסכות. הוא לא תלוי באנדרואיד, ולכן נבדק על JVM עם המודלים האמיתיים.
* **סביבת הרצה אחת למודלים: ONNX Runtime.** את מודלי ה-TFLite של MediaPipe ושל FaceRes המרתי ל-ONNX ‏(`tf2onnx`). כל מודל אומת מול המקור, עם הפרש מקסימלי של 1e-4 עד 1e-7. ב-EfficientDet תיקנתי שגיאת עיגול של ההמרה (`shared/tools/fix_onnx_resize.py`). המודלים נמצאים ב-`models/onnx`, ו-Gradle מעתיק אותם ל-assets של ה-APK. אין הורדות בזמן ריצה.
* **ממשק.** תפריט בראש המסך (הגדרות, וידאו או תמונה חדשים, אודות). ההגדרות נמצאות בדף משלהן ונשמרות אוטומטית. בחירת הצבע כוללת צבעים מוכנים (לבן, שחור, אפור, בז', כחול, כחול כהה, ירוק, ורוד) או צבע hex חופשי.
* **תמונות.** אפשר לבחור תמונה במקום סרטון. התמונה מנותחת באותם כללים, ואפשר לראות לפני ואחרי, לשנות החלטה לכל אדם, לשמור לגלריה (Pictures/BlueShield) ולשתף. בתמונה בודדת מבט אחד טוב על הפנים מספיק להחלטה, וסף הביטחון עדיין חל.
* **כתוביות וטקסט.** טקסט בהיר עם קו מתאר כהה, או קו המתאר עצמו, לעולם לא נצבע. אותו כלל פועל ב-shader של האנדרואיד, ברינדור של הדסקטופ ובתמונות.
* **מי מצונזר.** רק נשים בוגרות. המגדר נקבע משני מודלים של פנים שעובדים יחד (FaceRes ו-AgeGenderNet), כך שטעות של מודל אחד, למשל על אישה מבוגרת, מתוקנת על ידי השני. כדי לקבוע "גבר" נדרש ביטחון של 80% לפחות, כי פספוס של אישה חמור יותר. ילדה מזוהה לפי חציון הגיל המשוער לאורך הסרטון (מתחת ל-18), ואינה מצונזרת. גיל לא ידוע נחשב בוגר. כשאותו אדם מקבל שתי מסגרות (למשל כששוכבים), הן מאוחדות לפי הפנים המשותפות.
* **פנים, צוואר ומחשוף.** הפנים והצוואר לא מצונזרים. אם העור החשוף ממשיך מהצוואר לחזה (מחשוף), הצנזור מתחיל כסנטימטר מתחת לסנטר, וההחלטה נשמרת לאותו אדם כדי שלא תהבהב כשהראש זז. כתמים זעירים (בגדים בדוגמה, השתקפויות) מסוננים.
* **חפצים בצבע עור.** עור נחשב רק כשהוא על אדם, לפי מפת ה"אדם" של מודל הסגמנטציה. רחוק מכל אדם שזוהה הוא נחשב רק על גוף בגודל של אדם. כתם קטן ונפרד ליד אנשים, כמו כוס על השולחן, לא מצונזר. קצוות המסכה מותאמים לקווי המתאר האמיתיים בעזרת guided filter, ולא נראים "מרובעים".
* **דיוק המסכה.** כברירת מחדל ("איכות מקסימלית") העור מנותח בכל פריים: כל אדם נחתך ומנותח בנפרד ברזולוציה גבוהה, ופיקסלים בצבע שלא יכול להיות עור (כחלחל או כמעט שחור) נפסלים. ה-Optical flow סומך רק על אזורים עם מרקם, ולכן משטח חלק (שמיים, קיר, שולחן ביליארד) לא "גורר" מסכה. האיחוד הזמני מונע הבהוב, אבל לא משאיר מסכה במקום שבו העור כבר לא נמצא, כך שיד בתנועה לא משאירה שובל. כל מסכה מותאמת לפריים שלה לפי חותמת הזמן. גבול אדם חלקי (למשל פלג גוף עליון) לא נספר כאדם נוסף, כדי שההצבעות על המגדר לא יתפצלו.
* **ביצועים.** הפענוח רץ ב-thread נפרד, במקביל לניתוח. לולאות הפיקסלים הכבדות מתחלקות על כל הליבות. כל אדם מנותח בנפרד בכל פריים, והמעבר על הפריים כולו רץ רק בכל פריים מפתח שני. הסרטון לא נטען כולו לזיכרון. מודלים כבדים רצים רק בפריימי מפתח, ובמצבי "מאוזן" ו"מהיר" המסכות עוברות בין פריימי המפתח באמצעות Optical flow. NudeNet רץ במנות (batches), הפענוח והקידוד בחומרה, והסיבוב נשמר כמטא-דאטה. ‏`abiFilters`: ‏arm64-v8a ו-x86_64.
* **קבועים משותפים.** כל הספים והמשקלים נמצאים ב-`shared/pipeline.json`. האנדרואיד קורא את הקובץ ישירות, ובדיקת parity בדסקטופ מוודאת שהקבועים שם זהים.

## 5. הצנזור לנשים בלבד: איך זה עובד

שלבים נפרדים, בשתי הגרסאות:

| שלב | מה הוא עושה | מודל |
|---|---|---|
| **1. זיהוי אנשים** | תיבה לכל אדם | MediaPipe EfficientDet-Lite0 (קטגוריית person) |
| **2. סיווג מגדר** | לכל אדם במעקב: איתור הראש (מפת "עור פנים" או חיתוך עליון) ← זיהוי פנים ← יישור לפי העיניים ← הסתברות שזה גבר | BlazeFace ‏+ FaceRes ‏(MobileNet) |
| **3. מעקב אנשים** | זהות יציבה לאורך הסרטון: IoU ‏+ מראה (היסטוגרמת צבע) ‏+ Optical flow, וזיהוי מחדש של אדם שיצא מהפריים וחזר או אחרי חיתוך סצנה | — |
| **4. אזורים רגישים** | NudeNet מזהה אזורים, וכל אזור משויך לאדם שבתוך התיבה שלו | NudeNet v3 |
| **5. מסכות** | סגמנטציית עור. **כל פיקסל עור משויך לבעלים שלו**, לפי התיבה, ובחפיפה או מחוץ לתיבות לפי רוב רכיב העור המחובר. ‏**רק מי שמחליטים לצנזר נצבע** | MediaPipe Selfie Multiclass |

**ההחלטה (אף פעם לא מפריים בודד):**
* כל מבט בפנים הוא "הצבעה" במשקל לפי גודל הפנים וביטחון הזיהוי. ההצבעות מצטברות (log-odds) לאורך כל זמן הופעת האדם.
* **סף ביטחון** (ברירת מחדל 70%, ניתן לשינוי בין 51% ל-99%): ‏P(אישה) ≥ סף ← אישה. ‏P(אישה) ≤ 1−סף ← גבר. בין לבין ← **לא בטוח**.
* **מעט מדי ראיות** (פחות מ-6 מבטים או משקל מצטבר קטן מ-3) ← **לא בטוח**.
* **לא בטוח ← ברירת מחדל: צנזור** (נקרא בממשק "Censor (safe)"). אפשר לשנות ל-"Don't censor".
* **עור שלא שויך לאף אדם** מצונזר לפי אותה מדיניות, אבל רק כתם גדול מספיק (≥0.1% מהפריים) שיכול להיות אדם שלא זוהה. כתמים קטנים כמו מנורה או עץ לא נצבעים.
* **עקיפה ידנית:** אחרי העיבוד מוצגת רשימת האנשים עם תמונה, הערכה, ביטחון ומספר מבטים. לכל אדם אפשר לבחור Auto, ‏Censor או Don't, וללחוץ "Apply & re-render". הרינדור מחדש משתמש בניתוח השמור ולוקח שניות בודדות.
* **פנים לא נצבעות** אלא אם הופעל "Also cover faces", גם כשמודל הסגמנטציה טועה ומסמן פנים כ"עור גוף". תיבות הפנים במעקב תמיד נשארות נקיות.
* מצב **Everyone** מחזיר את ההתנהגות המקורית: צנזור כל אדם.

## 6. מגבלות ומקרי טעות אפשריים

* **סיווג מגדר מוידאו אינו אמין ב-100%.** המודל מעריך *מראה* מגדרי של פנים, לא זהות. בבדיקה על 373 פרצופים מתויגים, 92% מהפרצופים של נשים ו-100% מהפרצופים של גברים סווגו נכון ברמת הפריים הבודד. הבדיקה כללה רק שתי נשים שונות, כך שזו לא הערכה סטטיסטית רחבה. ההצבעה לאורך זמן מתקנת חלק מהטעויות, לא את כולן.
* **מקרים קשים:** פנים קטנות או רחוקות, פרופיל, גב למצלמה, משקפיים, תאורה חזקה מהצד, טשטוש תנועה, ילדים, איפור, פאות או כיסוי ראש. במקרים האלה התוצאה בדרך כלל "לא בטוח", ולכן **מצונזר** כברירת מחדל. בבדיקה: אישה עם משקפיים קיבלה תחילה "גבר" מ-3 מבטים בלבד. אחרי הקשחת כלל הראיות היא "לא בטוח" ומצונזרת.
* **אנשים צמודים או חופפים:** עור באזור החפיפה עלול להיות משויך לאדם הלא נכון. נצפה מקרה שבו תיבת "אדם" שגויה שכיסתה שני אנשים גרמה ליד של גבר להיצבע.
* **מודל הסגמנטציה** (256×256) חלש יותר על אנשים קטנים בפריים. במצב **Aggressive** מתווספת סריקה באריחים וגיבוי לפי צבע עור.
* **צוואר** נחשב "עור גוף" ולכן מצונזר אצל מי שמצונזר.
* **החלטה של אדם חלה על כל זמן הופעתו.** אם המעקב מחליף זהויות בין שני אנשים (למשל כשהם חוצים זה את זה), ההחלטה עלולה לעבור לאדם הלא נכון.
* **אנדרואיד:** לא נבדק על מכשיר (ראו סעיף 3), ולכן מהירות העיבוד בטלפון לא נמדדה. יש לצפות שהעיבוד יהיה איטי מזמן אמת, במיוחד במכשירים חלשים. השירות ממשיך לעבוד ברקע.
* **רישוי מודל המגדר:** ראו `models/README.md`, ובדקו את תנאי המקור לפני הפצה מסחרית.
* **תמיד עברו על התוצאה בתצוגת ההשוואה לפני הפצה.**

## 7. הדסקטופ המקורי

כל היכולות הקודמות נשמרו: העלאה בגרירה וכל הפורמטים, FFmpeg, ‏NudeNet, ‏MediaPipe/LiteRT, ‏Optical flow, זיהוי חיתוכי סצנה, מסכת סגמנטציה כחולה, מצב Aggressive, כיסוי פנים, תצוגה צד-לצד, סליידר השוואה, ניגון מסונכרן, השהיה/המשך/ביטול, אחוזי התקדמות, ייצוא MP4 ‏H.264 ברזולוציה, ב-FPS ועם האודיו המקוריים, ועיבוד מקומי.

**מה נוסף:** הבחירה "Women only / Everyone", סף ביטחון, מדיניות ל"לא בטוח", רשימת אנשים עם עקיפה ידנית ורינדור מחדש מהיר, ותוויות חיות על כל אדם בזמן העיבוד.

**מה נבדק:** ‏28 בדיקות אוטומטיות, בדיקת דפדפן מקצה לקצה, התקנה נקייה עם `./start.sh` והורדת מודלים מאפס, וקבצים ארוכים ובפורמטים שונים: MP4 ‏61 שניות עם אודיו, ‏1080p, ‏WebM ‏(VP9/Opus), ‏AVI ‏(MPEG-4/MP3). בקובץ המיוצא נבדקו הרזולוציה, ה-FPS, האודיו והמשך.
